# PoC 验收场景

> 完整端到端验收必须包含 Collector、Ingest API、原始存储和服务端确认。POC-02 的本地模拟接收端测试只记为 Collector 集成测试，不计为 E2E 完成。

## 平台运行

- 两个平台使用相同的切块、游标、上传和 Run 关联契约；
- Linux 已在 POC-02 验证进程单例、本地 IPC、状态落盘、重启续传和安全退出；
- Windows 实机的 Named Pipe、后台进程、状态落盘、重启续传和轮转验证合并到最终 E2E。

## 正常链路

- 使用一份经授权的 Codex JSONL，分两次追加并生成至少两个连续上传块；
- 每块客户端与服务端计算的字节数、SHA-256 一致；
- 服务端保存原始文件并完成最小解析；
- 内部视图显示记录数、记录类型、时间范围和解析器版本。

## 幂等

- 相同 `upload_id` 重复提交，原始文件和解析结果不重复；
- 相同 source/generation/offset 区间使用不同 `upload_id` 重试，行为必须有明确记录和测试；
- 服务端确认前本地游标不推进，失败后重传同一区间。

## 文件增长与边界

- 文件末尾放置一条未结束的 JSON；本轮不上传该行，下轮补全后只上传一次；
- 新增内容超过单块上限时拆成多个连续块，边界只能落在换行后；
- 服务端拒绝 offset 空洞和重叠但内容不一致的块。

## 截断与轮转

- 文件大小小于已确认 offset 时创建新 generation，并记录 `source_truncated`；
- 同路径文件身份变化时创建新 generation，并记录 `source_rotated`；
- 旧 generation 的原始块和解析结果保持可重放。

## Schema 变化

- 增加一个未知顶层记录类型；
- 原始文件正常保存；
- 解析结果标记 unknown 类型，不整包失败。

## 损坏数据

- 使用只包含脱敏测试内容的夹具制造一条非法 JSON；
- 解析器定位文件内行号和字节位置；
- 原始文件仍保留；
- 修复解析器或夹具后能够重放。

## 安全

- 仓库和测试输出不包含 JWT、Cookie、API token；
- 页面不展示消息正文、工具参数和工具输出；
- 未授权样本不得进入 fixtures。
