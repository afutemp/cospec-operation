# 运营看板数据可用性

> 更新日期：2026-09-01  
> 本表描述的是当前代码实际能够采集、解析和查询的数据，不代表最终规划范围。

## 标记说明

- 【已采集】：当前 Collector、服务端解析和查询链路已经能够提供。
- 【部分可得】：已有部分事实，但不能按最终业务口径解释。
- 【待接入】：来源和口径已经确定，但当前链路尚未采集。
- 【暂不采集】：当前阶段明确不做，不应出现在首版看板中。
- 【来源不可得】：宿主当前没有提供可靠字段，不能通过推断补齐。

## 最前面需要注意的缺口

- [x] 【已采集】匿名终端 ID。Collector 首次启动时生成并保存在用户级状态目录，插件和 Collector 正常升级不会改变；服务端可以按周期去重为“活跃终端数”。旧上传没有该字段时不进入终端数，单独计入缺失覆盖。
- [ ] 【待接入】IPD 人员与产线。只允许采用 IPD 返回的信息；未配置或未返回时保持为空，不从本机账号、路径或 JSONL 推断。
- [ ] 【待接入】大／小工作流。直接采用 `cospec-router` 中规划人员的选择结果；当前尚未集成 Router，因此不能统计大小工作流分布。
- [ ] 【待接入】工作流、Stage 和 Skill 的权威执行边界。当前 JSONL 不能可靠判断具体执行了哪个 Cospec Skill。
- [ ] 【待接入】16 个重点 Skill 的调用量、耗时、Token、工具调用和明确失败归属。Run 级资源已经可得，但尚不能归属到 Skill。
- [ ] 【待接入】用户等待 Cospec 返回结果的时间。当前只有宿主首末记录跨度，包含用户停顿，不能当作执行耗时或用户等待时间。
- [ ] 【待接入】工作流的业务结束状态。Collector 的 `finish` 只控制停止继续采集，当前上传协议没有把业务完成状态提供给服务端看板。

上述项目在接入前，页面必须显示“尚未采集”或“未标注”，不能显示为 0。

## 当前已经可用的数据

- [x] 【已采集】Run 数量与按日趋势。
- [x] 【已采集】活跃匿名终端数，以及有／无终端 ID 的 Run 覆盖范围。
- [x] 【已采集】Codex／Claude Code 数据源及 Agent 版本。
- [x] 【已采集】Cospec 插件版本随上传块保存。
- [x] 【已采集】JSONL 块数、字节数、offset、接收时间和解析状态。
- [x] 【已采集】消息记录数及用户／Agent 角色分布。它表示消息记录，不称为对话轮次。
- [x] 【已采集】输入、输出、缓存读取、缓存写入／创建、推理输出等宿主明确提供的 Token。
- [x] 【已采集】模型分布，以及模型字段和各类 Token 的数据覆盖范围。
- [x] 【已采集】工具调用量、工具名称和调用耗时；支持 P50、P90、累计时间及去除并发重叠后的经过时间。
- [x] 【已采集】Claude Code 有明确 `is_error` 的工具结果。
- [x] 【已采集】Codex JSONL 中实际保留结构化 `exit_code` 的工具结果。
- [x] 【已采集】主会话与显式关联子代理的数量、层级、模型和资源汇总。
- [x] 【已采集】Codex／Claude Code 的上下文压缩次数；Claude Code 可区分 JSONL 明确记录的自动和手动压缩。
- [x] 【已采集】Codex JSONL 明确给出的上下文上限。

## 已有数据但不能直接按业务指标解释

- [x] 【部分可得】工具明确失败次数。Claude Code 覆盖较好；Codex 是否有退出码取决于调用链，必须同时展示状态覆盖率，明确失败只能视为下界。
- [x] 【部分可得】Run 时间。当前是 JSONL 第一条到最后一条有效记录的跨度，包含用户停顿，不是纯执行时间，也不代表工作流已完成。
- [x] 【部分可得】Cospec Run 关联。当前验证由命令手工传入 `cospec_run_id`；尚未由 `cospec-router` 自动创建并传入。
- [x] 【已采集】插件版本。可按版本筛选，并展示各版本的 Run 数、活跃匿名终端数及终端字段缺失 Run 数。
- [x] 【部分可得】工具状态。存在调用但没有直接结果证据时保持“未知”，不从输出正文猜测成功或失败。
- [x] 【部分可得】子代理。新版采集可以关联，旧格式数据不可事后补推；当前 Windows 文件发现仍待实机验收。

## 当前明确不可得或暂不纳入

- [ ] 【来源不可得】Claude Code 会话 JSONL 的上下文上限。保持为空，不根据模型名称推断。
- [ ] 【来源不可得】Codex 未保留结构化 `exit_code` 时的工具业务结果。不读取正文关键词猜测。
- [ ] 【暂不采集】综合效果分、质量分和业务价值判断。
- [ ] 【暂不采集】运营目标值、达标率和红绿灯。
- [ ] 【暂不采集】产物、Demo、Evaluator、知识库消费和 IPD 后续采用效果。
- [ ] 【暂不采集】个人排名。后续人员信息只用于覆盖分析、筛选和问题下钻。
- [ ] 【明确不做】Agent 首次响应等待时间。Cospec 入口是 `cospec-router`，首次响应通常只是让用户选择工作流；该时长主要反映菜单返回速度，不能代表需求澄清、研究、TR1／TR2、具体 Skill 或有效结果的等待时间，因此不进入领导周报、运营指标或近期开发任务。

只有在后续获得 Router 选择完成、Skill 开始／结束以及“有效结果或下一决策点”的明确事件边界后，才重新评估用户等待时间；当前不从 JSONL 的第一条 Agent 回复近似推断。

## 对首版周报页面的影响

当前能够可信展示：每周 Run 数及趋势、Agent／版本／模型分布、Run 资源分布、工具调用与明确失败、子代理使用、上下文压缩和采集解析状态。

以下模块要保留设计位置，但在数据接入前标记“尚未采集”：人员／产线覆盖、大小工作流分布、具体 Skill 使用与耗时、用户等待时间、工作流完成情况。
