# Cospec 运营平台页面划分方案 v0.2

> 状态：待评审
>
> 本文只确定页面职责、指标、趋势和交互，不代表当前页面已经按此完成改造。

## 1. 设计目标

平台服务两类核心场景：

1. 对领导汇报 Cospec 的推广规模、工作流运行和交付进展。
2. 帮助运营及研发发现问题，并下钻到具体工作流和 Run 排查。

页面不再把汇报、专项分析、问题排查和技术明细混在同一个“运营总览”中。

## 2. 一级导航

当前阶段开放运营概览、工作流分析、SKILL 分析和推广使用；管理员额外显示过渡期用户管理入口。问题排查保留为下一阶段页面。

| 页面 | 核心问题 | 主要用户 |
|---|---|---|
| 运营概览 | Cospec 当前推广和运行得怎么样？ | 领导、运营人员 |
| 工作流分析 | 哪些工作流在运行，推进和交付情况如何？ | 运营人员、规划负责人 |
| SKILL 分析 | 哪些 SKILL 被使用，哪些值得优化？ | 运营人员、SKILL 维护者 |
| 推广使用 | 哪些产线和人员在使用，覆盖与持续使用如何？ | 运营人员、推广负责人 |
| 问题排查 | 当前有哪些问题需要关注和介入？ | 运营人员、研发人员 |
| Run 查询 | 查看单次运行的采集、解析、SKILL、工具和产物事实 | 研发人员、运营人员 |
| 用户管理 | 管理 SSO 接入前的本地看板账号和权限 | 管理员 |

辅助能力：

- 指标口径在对应的卡片、图表或字段旁就地说明，不设置统一产品入口。
- 登录后续接入 SSO；当前本地账号模块与运营数据隔离，届时可整体替换。
- 系统运行状态后续放入设置或页脚，不占用主要运营导航。

## 3. 统一时间范围

所有一级分析页面使用同一套时间选择器，但可采用不同默认值。

### 3.1 自然周期

适合正式汇报，按用户所在时区的自然日历计算。

| 选项 | 范围 |
|---|---|
| 当天 | 今天 00:00 至当前时间 |
| 本周 | 本周一 00:00 至当前时间 |
| 本月 | 本月 1 日 00:00 至当前时间 |

### 3.2 滚动周期

适合持续观察和问题排查。

| 选项 | 范围 |
|---|---|
| 最近 24 小时 | 当前时刻向前 24 小时 |
| 最近 7 天 | 当前时刻向前 7×24 小时 |
| 最近 30 天 | 当前时刻向前 30×24 小时 |

### 3.3 自定义

- 用户可选择精确到时间的起止范围。
- 页面显示实际起止时间，避免只显示“本周”等模糊标签。
- URL 同时保留范围类型和实际起止时间，例如 `range=week&from=...&to=...`。
- 页面间下钻时必须继承当前时间范围，不切换成目标页面默认范围。

### 3.4 默认值与对比口径

| 页面 | 默认时间 |
|---|---|
| 运营概览 | 本周 |
| 工作流分析 | 本周 |
| SKILL 分析 | 本周 |
| 推广使用 | 本月 |
| 问题排查 | 最近 24 小时 |
| Run 查询 | 最近 7 天 |

- 当天对比昨天同期。
- 本周对比上一个自然周同期。
- 本月对比上一个自然月同期；完整月报需要时再补充完整自然月对比。
- 最近 24 小时、7 天、30 天分别对比紧邻此前的等长周期。
- 百分比变化同时展示上期原始值，避免只看涨跌比例。

## 4. 运营概览

### 4.1 页面职责

回答“Cospec 当前推广和运行得怎么样”，用于日常查看和汇报。

不在该页面展示具体人员姓名、工具失败明细、长时间无活动 Run 等排查内容，也不使用“领导周报”作为页面名称。

### 4.2 核心指标

- 活跃用户（估算），并拆分已识别人员和匿名终端
- 工作流运行数
- 大需求、小需求、自定义工作流数量
- 正式产物数量及工作流覆盖率，作为工作流运行卡片的补充信息
- 涉及产线数量
- 各项与上一可比周期的变化

### 4.3 趋势图

#### 活跃用户趋势

- 活跃用户估算：折线图
- 已识别人员、匿名终端：分项折线图

#### 工作流启动趋势

- 工作流运行数：按大需求、小需求、自定义和未标记类型堆叠的柱状图，柱高表示当日总数

### 4.4 摘要

- 产线覆盖摘要，不展示具体人员排名

### 4.5 交互

| 操作 | 目标页面 |
|---|---|
| 点击使用人数、产线覆盖 | 推广使用 |
| 点击工作流数、产物覆盖 | 工作流分析 |
| 点击重点 SKILL | SKILL 分析 |
| 点击趋势图时间点 | 对应分析页，并带入该时间桶 |
| 点击异常提醒 | 问题排查 |

## 5. 工作流分析

### 5.1 页面职责

回答“哪些工作流在运行，推进和交付情况如何”。

### 5.2 指标与趋势

- 工作流总数及趋势
- 大需求、小需求、自定义工作流分布及趋势
- 完成、失败、中断、进行中分布及趋势
- 已结束工作流完成率及趋势
- 阶段进入、完成、失败、中断和跳过情况
- 正式产物数量及覆盖趋势

完成率趋势必须同时显示已结束样本数，避免小样本百分比误导。

### 5.3 过滤

- 时间范围
- 工作流类型
- 工作流状态
- 产线
- 人员
- Agent 类型和版本
- Cospec 版本
- 是否有正式产物

### 5.4 明细与下钻

工作流列表展示：

- 工作流名称、类型和状态
- 人员、工号和产线
- 开始时间与最后活动时间
- 使用的重点 SKILL
- 正式产物数量
- 明确工具失败数量

交互链路：`指标或趋势 → 工作流列表 → Run 详情`。

## 6. SKILL 分析

### 6.1 页面职责

回答“哪些 SKILL 被使用，哪些值得优化”。SKILL 是运营对象，可以做排序和重点关注。

### 6.2 SKILL 列表

- SKILL 名称
- 涉及工作流数
- 执行次数
- 成功、失败和未结束次数
- 活跃时长 P50、P90
- 等待用户时间
- 工具调用与明确失败数
- 正式产物数量

### 6.3 排序与过滤

支持按以下方式排序：

- 执行次数最多
- 涉及工作流最多
- P90 时长最长
- 执行失败最多
- 工具失败最多

支持过滤：

- 时间范围
- 工作流类型
- 产线
- SKILL 名称下拉选择（支持输入检索）
- 是否为重点 SKILL

时间范围、工作流类型和产线是全页筛选，统一放在所有汇总与图表上方，选择后立即生效，不设置多余的确认按钮。SKILL 名称下拉和排序控件放在明细列表标题区，只调整下方列表，不改变页面上方的汇总卡片与使用趋势。

### 6.4 趋势

#### 使用趋势

选择一个或多个重点 SKILL，对比：

- 执行次数
- 涉及工作流数

默认最多同时展示 5 个 SKILL。

#### 执行质量趋势

针对选中的 SKILL 展示：

- 成功、失败和未结束次数
- 活跃时长 P50、P90
- 等待用户时长
- 工具失败数

### 6.5 SKILL 详情

- 核心指标和时间趋势
- 执行时长分布
- 等待用户占比
- 工具失败情况
- 使用该 SKILL 的工作流、人员和产线
- 相关 Run

没有目标值时，只提供耗时排序，不直接定义为“超标”或“异常”。

## 7. 推广使用

### 7.1 页面职责

回答“哪些产线和人员在使用，推广覆盖到哪里”。以产线为主要分析对象，人员作为下钻对象，不用于个人绩效评价。

### 7.2 指标与趋势

- 活跃用户及趋势（区分已识别人员与匿名终端）
- 覆盖产线数
- 身份信息覆盖率
- Agent 类型和版本覆盖
- Cospec 版本覆盖

“首次观测”只表示系统首次看到该工号，不等同于公司新增用户。

身份关系按实际使用约束处理：一个终端只归属一个人员，一个人员可以有多个终端。Run 原始身份快照保持不变；查询时可用同工号已知产线补全缺失值，或在终端只有唯一已知人员时补全人员，并明确标记为“后续补全”。

### 7.3 产线列表

- 产线名称
- 使用人数
- 工作流数
- 工作流数

默认按工作流数量排序。尚未关联人员的匿名终端单独展示，不归入未知产线。

### 7.4 产线与人员下钻

交互链路：`产线 → 人员列表 → 人员相关 Run`。

人员列表展示：

- 姓名
- 工作流数

不在运营概览展示人员姓名，不制作人员排行榜。个人分析用于推广跟进和问题定位，不用于绩效评价。

## 8. 问题排查

### 8.1 页面职责

回答“当前有哪些问题需要运营或研发介入”。该页面与运营概览分离。

### 8.2 问题分类

- 工作流失败
- 工作流中断
- 工具调用明确失败
- 长时间无活动
- 已完成但没有正式产物
- 身份或产线信息缺失
- SKILL 标记不完整
- SKILL 耗时较长

### 8.3 问题信息

每类问题展示：

- 问题数量
- 影响工作流数
- 影响人员或产线数
- 最近发生时间
- 数据口径说明

“长时间无活动”只是当前存量排查信号，不代表工作流失败或中断。

### 8.4 趋势

按时间展示：

- 工作流失败
- 工作流中断
- 工具失败
- 完成无产物
- 身份信息缺失

长时间无活动采用单独的存量趋势，不与事件发生次数直接堆叠。

### 8.5 下钻与后续闭环

当前阶段：`问题分类 → 问题 Run 列表 → Run 详情`。

后续可增加：

- 标记已确认
- 处理备注
- 指派跟进人
- 忽略误报
- 问题关闭状态

## 9. Run 查询与详情

### 9.1 页面职责

作为所有运营页面共用的最终事实下钻，也是研发人员直接查询运行记录的技术入口。

### 9.2 查询条件

- 时间范围
- 工作流类型和状态
- Agent 类型和版本
- Cospec 版本
- 工号和产线
- SKILL
- 是否有正式产物
- 是否有明确工具失败
- 无活动时长
- 身份是否缺失

所有查询条件写入 URL，支持刷新、浏览器前进后退和分享链接。

### 9.3 Run 详情

- 工作流和人员快照
- JSONL 分块及解析状态
- SKILL 执行与时长
- 等待用户时间
- 工具调用和明确失败
- Token、上下文压缩和子代理
- 正式产物目录、查看和下载
- 工作流阶段及结束状态

## 10. 图表统一规则

### 10.1 时间粒度

| 时间范围 | 默认粒度 |
|---|---|
| 当天、最近 24 小时 | 小时 |
| 本周、最近 7 天 | 天 |
| 本月、最近 30 天 | 天 |
| 较长的自定义范围 | 周 |

### 10.2 通用交互

- 悬停显示时间、原始值及必要的分子分母。
- 支持图例开关。
- 点击时间点进入明细并继承过滤条件。
- 无数据时显示“暂无数据”，不使用 0 冒充已统计结果。
- 百分比指标同时展示样本数。
- 同一颜色在不同页面表示相同状态，例如完成、失败、中断、进行中。

## 11. 数据口径说明

不提供独立的“数据口径”页面或全局入口。以下口径应在使用该数据的卡片、图表或字段旁通过简短文案、提示图标或悬浮说明就地解释：

- 活跃用户估算 = 按 IPD 工号去重的已识别人员 + 未关联人员的匿名终端；匿名终端可能属于同一人员，不作为精确人数。
- 工作流完成率只计算已经明确结束的工作流。
- 进行中表示尚未收到结束事件，不自动根据无活动时间改成失败。
- SKILL 活跃时长剔除可明确识别的等待用户回复时间。
- 工具失败只统计工具结果中具有直接失败证据的调用。
- 正式产物只统计 manifest 登记并成功上传的文件。
- 产线采用 Run 启动时 IPD `proposer_dept` 快照。
- P50、P90 的含义及小样本风险。
- 各类数据采用的时间归属字段。

## 12. 改造建议顺序

1. 重建路由和一级导航，拆出五个运营页面。
2. 统一时间范围组件、URL 状态和下钻参数。
3. 精简运营概览，完成两张核心趋势图。
4. 建设工作流分析和明细下钻。
5. 建设 SKILL 列表、趋势和详情。
6. 建设以产线为主的推广使用页面。
7. 将现有异常清单迁入独立问题排查页面并补趋势。
8. 为各页面的指标、图表和字段补充就地口径说明。
9. 使用领导汇报、运营分析、问题排查三条用户故事完成端到端验收。

## 13. 待确认事项

- 是否认可上述六个一级导航及其顺序。
- “推广使用”是否保持以产线为主、人员为下钻对象。
- 运营概览是否只保留两张核心趋势图，不展示具体排查明细。
- 问题排查当前是否保持只读，暂不增加指派、备注和关闭状态。
