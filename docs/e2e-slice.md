# 首条端到端切片

## 输入

一份已完成结构验证、经授权用于测试的 Codex 会话 JSONL。

## 流程

1. 验证者读取 Agent Session ID、生成或恢复 Cospec Run ID，并手动执行 `ensure` 拉起或复用 Collector；
2. Collector 通过 Session ID 定位 JSONL，登记 Run 开始边界并读取上次服务端已确认 offset；
3. 截取新增且以换行结束的完整记录，生成带 offset、generation、hash 的上传包与环境快照；
4. 测试客户端上传，成功确认后推进本地游标；
5. 服务端校验并按 `upload_id` 幂等保存不可变原始文件；
6. 工作流结束时手动调用 `finish`，登记 Run 结束边界；
7. 解析器逐行验证 JSON，输出记录类型、数量、会话标识、时间范围和诊断；
8. 解析结果记录解析器版本，并支持从原始文件重放；
9. 内部视图展示上传、保存、解析和重放状态。

## 完成标准

- 同一 offset 区间重复上传不重复保存；
- 数据块 hash 在本地、传输后和服务端一致；
- 上传失败后从未确认 offset 继续，不漏传；
- 文件末尾未完成行留待下一次采集；
- 文件截断或轮转产生新 generation，不覆盖旧块；
- Collector 重复 `ensure` 不产生重复进程，Run 能精确关联到 Session ID 和 offset 区间；
- 未知记录类型不会导致整包失败；
- 非法 JSON 行能够定位；
- 解析器升级后可从原始文件重放；
- 页面能够看到文件、上传状态、解析状态、记录数量和类型分布；
- 不依赖最终业务 Schema 或运营指标。
