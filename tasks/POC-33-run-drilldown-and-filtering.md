# POC-33 Run 下钻与组合过滤

- [x] 周报卡片可继承当前时间、人员和产线范围下钻到 Run
- [x] 提供工作流类型、终态、工具失败、无活动、重点 SKILL 和人员快捷下钻
- [x] Run 列表支持时间、类型、状态、Agent、工号、产线、SKILL、产物、工具失败和无活动时长组合过滤
- [x] Run 明细展示工作流、人员、SKILL、产物数和明确工具失败数
- [x] 筛选条件写入 URL，刷新、前进后退和分享链接时保留
- [x] 服务端验证过滤口径和非法参数
- [x] Chromium 按运营故事验证“周报 → 大需求 → SKILL → Run 详情 → 产物下载”

## 运营故事验收

周一，运营人员查看本周汇报，发现大需求已有运行记录。他点击“大需求”，列表继承本周范围，只显示对应 Run；继续叠加 `tr1-requirements-spec`，定位到执行该重点 SKILL 的规划人员和产线，刷新页面条件仍在，随后进入 Run 查看执行事实并下载正式产物。

当前链路能满足这个故事。为了避免下钻后仍需猜测 Run，列表补充了工作流状态、人员、产线、SKILL、产物数和明确工具失败数；快捷入口也覆盖了失败、中断、工具失败和长期无活动等排查场景。

## 后续优化边界

- 当前规模约 20 人，服务端先在内存中组合过滤；数据量明显增长后再下推为 SQL 索引查询。
- “重点 SKILL”和人员快捷入口先展示前 5 项，完整范围仍可在筛选栏输入。
